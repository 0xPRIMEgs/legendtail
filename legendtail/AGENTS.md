# Legendtail instructions

For game-asset work, read [LEGENDTAIL.md](LEGENDTAIL.md) and the task-relevant guides. For work on this documentation repository, maintain the same evidence standards.

## Asset work

- Inspect references, existing assets, and the target loader before assuming proportions, axes, hierarchy, or file layout.
- Make an explicit brief and part budget. Count final triangles including mirrored instances and agreed accessories.
- Prioritize recognizable silhouettes and articulation. Put surface graphics in textures when they do not need physical depth.
- Use UV projections derived from real surface coordinates. Check front/back continuity, boot sides/toes/soles, mirrored details, and atlas filtering.
- Preserve names, pivots, attachment order, and local bases for compatible replacements. Verify motion beyond the neutral pose.
- Separate concept art from actual model renders and target-runtime evidence.
- Validate exported geometry, material/UV data, animation, and package contents. Report untested targets plainly.
- Fix the requested defect without discarding earlier approved revisions. Keep source and output revisions aligned.

## Documentation work

- Keep the main protocol concise; place worked detail in the guides and link it from the reading map.
- Mark numeric budgets as measured examples or suggested starting points. Never imply that a suggested budget is a hardware limit.
- Scope MA-specific details to the inspected version. Do not replace pivot-based guidance with obsolete bone-system assumptions.
- Preserve the distinction between user feedback, measured checks, engineering guidance, and untested proposals.
- Use relative Markdown links and exact, case-sensitive filenames. Verify links, tables, equations, and examples after editing.
- Do not add fake CLI commands, installation claims, benchmarks, supported-platform claims, or a published GitHub URL.
- Keep private account links, credentials, internal workspace paths, and unrelated personal history out of public-facing documentation.
- Change a repeated rule in its canonical guide and update entry-point summaries only when necessary.
- Any new automation must be executable and tested before it is described as available. This edition contains Markdown guidance, not executable modeling tools.
